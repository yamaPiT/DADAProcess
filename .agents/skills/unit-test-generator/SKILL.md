# ユニットテスト自律生成・修復 (Unit Test Generator)

本スキルは Phase 4 で `programmer` が単体テスト作成・実行・修復を自律完結する手順です。開始・完了時に思考過程（①現在地 ②判断の根拠 ③次の一手）を出力します。

## 1. 実行手順
1. **環境特定**: `SW205`（8.2節）および設定ファイルからテストフレームワークを特定する（Python 標準案件では `unittest`）。
2. **内部テスト計画**: 対象 `UNIT-ID` の公開 IF・検証条件（`SW205`/`SW105`）から正常系・異常系・境界値を計画する。**単体テスト計画を Product Owner へ承認依頼しない。**
3. **生成・配置**: テストコードは `tools/` ではなく**必ず `tests/` 配下（例: `tests/test_<name>.py`）へ配置**し、`docs/guidelines/coding_guidelines.md` に従い AAA パターンと対応 **`UNIT-ID`・`TC-ID`**（該当時）を明記する。
4. **自律デバッグループ**: テストを実行し、失敗時は人間へ都度報告せず `SW105`/`SW205` を正として実装またはテストを修正・再実行する。
5. **上限と打ち切り**: **同一テストが5回連続で失敗**したらループを打ち切り、`docs/artifacts/BUG101_バグ管理表.md` へ記録して Product Owner へ報告する（設計不備なら Phase 3 差し戻し提案）。
6. **台帳更新**: 全件グリーン後に `docs/process/impl_progress.md` を更新し、`programmer` へ件数を報告する。

## 2. 禁止事項・自己チェック
- 期待値弱化・削除・`skip` によるテスト改ざん、Assert なしテスト計上、虚偽グリーン報告、PO への単体計画承認依頼を禁止する。
- [ ] `tests/` 配下に配置し、AAA と `UNIT-ID`/`TC-ID` 明記・全件グリーン（または5回停止報告）を完了したか
