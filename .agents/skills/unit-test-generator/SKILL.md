# ユニットテスト自律生成・修復 (Unit Test Generator)

本スキルは、実装フェーズ（Phase 4）において、ユニットテストを人間の関与なしに裏側で完結させるための物理的な自動実行ループの手順です。

## 実行手順 (Mechanical How)

1. **フレームワークの特定**:
   - プロジェクトの設定ファイル（`package.json`、`pyproject.toml` 等）から既存のテストフレームワーク（`vitest`、`pytest` 等）と実行コマンドを特定します。未導入の場合は、言語標準のフレームワークを導入します。
2. **内部計画 (No Human Review)**:
   - 対象ユニット（UNIT-ID）の「検証条件」（SW205）に基づき、テスト計画をAIコンテキスト内部だけで立案します。正常系に加え、境界値・異常系を必ず含めます。
   - **【厳守】この計画をProduct Owner（人間）に提案・レビュー依頼してはいけません。即座に次へ進みます。**
3. **テストコードの生成と配置**:
   - プロジェクト固有のテストフレームワーク構文に従い、テストファイルを生成します（例: `*.test.ts`）。
   - `docs/guidelines/coding_guidelines.md` に従い、AAAパターンのコメントと対応ID（UNIT-ID/TC-ID）を明記します。
   - **対応IDの明記は省略できません。** 機械チェック（`python tools/dada_check.py code`）は、このIDを手がかりに「テストが存在しないTC-ID」を検出します。IDがないとテストを書いても未実装と判定されます。
4. **完全自律デバッグループ**:
   - ターミナルコマンドでテストを実行します。
   - エラーが発生した場合は**人間に報告せず**、自らエラーログを読み取り、コードまたはテストを修正して再実行します。
   - 修正の判断基準: **SW105の検証条件・SW205の設計が常に「正」**。テストが正しく実装が間違っていればコードを直し、テストが設計を誤解していればテストを直します。
   - すべてのテストが「グリーン（成功）」になるまで、このループを自律的に繰り返します。
5. **スタックした場合の脱出ルール（無限ループ防止）**:
   - **同一のテストが5回連続で失敗**した場合、そのループを打ち切ります。
   - 状況を `docs/artifacts/BUG101_バグ管理表.md` に記録（現象・試した修正・仮説）し、Product Ownerに「自律解決できない問題」として報告して指示を仰ぎます。
   - 設計自体の問題が原因と判断した場合は、`programmer` スキルの「差し戻し手順」に従いPhase 3への差し戻しを提案します。
6. **最終完了報告**:
   - オールグリーンを達成した後のみ、上位のオーケストレーター（`dada-process` スキル）に対して「実装と単体テストが完了した」という結果のみを報告してください。

## 禁止事項
- **テストの改ざんによるグリーン化の禁止**: テストを通すために、期待値を実装の現状に合わせて弱める・テストを削除する・skipすることを禁止します。（`skip` `only` `xit` 等による無効化は機械チェックが検出し、`code-reviewer` がテスト改ざんとして監査します）
- **検証なしテストの禁止**: Assertのない「実行するだけ」のテストを成果として数えないこと。
- **虚偽報告の禁止**: 実行していないテストを「グリーン」と報告しないこと。報告には実際のテスト実行結果（件数）を添えること。
