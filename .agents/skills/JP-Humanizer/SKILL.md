# JP-Humanizer: 日本語構造推敲スキル

> **著作権・出典表示**: 本スキルは、大賀愛一郎氏（`nanaism` / ALGO ARTIS）のオープンソーススキル『yomiyasu』（MIT License）の設計思想と逆瀬川氏（`@gyakuse`）による Qiita 7万記事定量分析の知見を参考に、ASDoQ文書品質モデル（ADL-1.1）と `tools/style_check.py` を組み合わせて再構築した派生スキルです。ライセンス全文は `.agents/skills/JP-Humanizer/LICENSE.md` を参照してください。

## 1. モード分岐・絶対不変条件・思考過程
- **単体利用時**: 単体推敲依頼では **DADAプロセス（Phase 0〜5・`SW105` 作成・`[DADA` 進行表示）を起動しない**。
- **思考過程3項目**: 開始・完了時に **①現在地 ②判断の根拠 ③次の一手** を必ず出力する。
- **絶対不変条件**: (1) **意味の完全保持**: ID（`REQ-001` 等）、数値・単位、条件分岐、肯定／否定極性（「〜しない」「禁止」）、義務の強さ（Must/Should/Could）を一切変更・削除しない。(2) **情報の不増補**: 原文にない仕様・理由・具体例を創作しない。

## 2. 自然な日本語にする8つの推敲観点
1. **比喩・擬人化・大げさな修辞の排除** `[ASDoQ:可読性-表現適切性]`: 「静かに壊れる」「解像度を上げる」「鍵を握る」「過言ではない」等を事実・具体動作へ直す。
2. **AI頻出スラングの具体化** `[ASDoQ:理解容易性-非曖昧性（一意性）]`: 「効く」「担保」「一気通貫で」「シームレスに」を検証可能な具体動詞へ直す。
3. **過剰否定対比の解消** `[ASDoQ:可読性-簡潔性]`: 「単なるAではなくB」を肯定文の直接記述へ直す。
4. **英語由来ダッシュ・コロン構文の解消** `[ASDoQ:規範適合性-記法適合性]`: 文中の `—` / `―` / 「結論：」を読点・句点・括弧へ直す。
5. **過剰装飾の抑制** `[ASDoQ:可読性-表記適切性]`: 1段落の太字を1〜2箇所に絞り、2〜3文の散文を機械的に太字箇条書きへ分解しない。
6. **前置き・機能動詞結合の簡潔化** `[ASDoQ:可読性-簡潔性]`: 「言うまでもなく」を削り、「〜の検証を行う」「〜することが可能である」を「〜を検証する」「〜できる」へ直す。
7. **主述明確化と長文分割** `[ASDoQ:規範適合性-文法適合性]`: 110字超または読点5個以上の文を1文1義へ分割する。
8. **条件先出しと文末リズム自然化** `[ASDoQ:整合性-一貫性]`: 条件を文頭に出し、同一文末の4文以上連続を避ける。

## 3. 実行手順（単体・局所推敲共通 / 上限2回）
1. **スナップショット保存**: `python tools/style_check.py snapshot --input <対象.mdパス> --summary`
2. **検出と局所推敲**: `python tools/style_check.py lint --input <対象.mdパス>`（図表・用語検査時は `python tools/asdoq_lint.py --input <対象.mdパス> --profile general` 併用）で検出箇所のみ8観点で修正する（指摘0件ならリライト省略）。
3. **意味保持検証**: `python tools/style_check.py verify --input <対象.mdパス>` で終了コード `0` を確認する。変化時は即復元する。**修正試行は最大2回**とし、超過時は無理に書き換えず原文の意味を優先保持して報告する。
4. **報告**: 単体利用時は改善ポイント（3〜5点）と `verify` 要約1行のみ報告する。

## 4. 禁止事項・自己チェック
- ID・数値・単位・否定表現の削除/改変、`verify` 省略、3回以上の推敲強行、単体依頼での DADA起動を禁止する。
