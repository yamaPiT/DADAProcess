# ドキュメント出力職人 (Document Writer)

本スキルは、各フェーズのペルソナスキル（作成者）が構築・修正した開発ドキュメントを、ファイルシステムへ安全かつ正確に反映させるための物理的な操作手順である。

## 実行手順 (Mechanical How)

1. **保存先の特定とパス固定**:
   - 開発成果文書（`SW105` / `SWP6` / `SW205`）および管理帳票（`REV101_*` / `BUG101` / `TM101`）は、必ず `docs/artifacts/` ディレクトリ配下の所定パスに保存する。
   - プロセス状態ファイル（`last_phase_summary.md` / `impl_progress.md` / `autoloop_log.md` / `eval_report.md`）は、`docs/process/` ディレクトリ配下に保存する。
2. **分割書き出し（長文崩れ対策）**:
   - 長い文書を一度に全文生成すると、後半で構造が崩れたり内容が浅くなったりしやすい。新規作成時はスケルトン（または指定テンプレート）をコピーしたうえで、**章（見出しレベル2 `##`）単位で順次編集・追記**する。
3. **安全な差分更新の徹底**:
   - 既存のファイルを更新する場合、無検証で全文を上書きせず、変更前の内容を確認して対象箇所のみを編集（差分更新）し、既存の承認済み記述やIDの意図しない欠落を防ぐ。
4. **フォーマットと固定ラベルの維持**:
   - Markdownの表組み、Mermaid図の構文、見出しの階層、および機械チェック（`tools/dada_check.py`）が読み取る固定ラベル（`#### REQ-001:` / `#### UNIT-001:` / テスト項目表の列名等）が崩れないよう正確に出力する。
5. **書き出し後の実ファイル検証（必須）**:
   - 保存が終わったら、記憶に頼らず**必ず保存済みファイルを読み直して**以下を確認する。
     - 見出しの階層・順序がスケルトンまたは指定テンプレートと一致しているか
     - 表の列数が揃っているか、Mermaidのコードブロックが閉じているか
     - スケルトンの【AIへの指示】コメントや記入例（`REQ-EX` / `TC-EX` / `UNIT-EX` / `ADR-EX`）が残っていないか
   - 崩れや残骸を見つけた場合は、その場で修正してから次へ進む。
6. **日本語推敲スキル（`JP-Humanizer`）との連携**:
   - 開発成果文書（`SW105` / `SWP6` / `SW205`）の書き出し後は、各作成者スキルの手順に従い、`python tools/style_check.py snapshot` → `JP-Humanizer` による推敲と `style_check.py lint` → `style_check.py verify` の3ステップへ引き継ぐ。
   - また、Product OwnerからOffice文書への変換を求められた場合は、まず本スキルで `.md` を確定させる。その後にスキル `.agents/skills/office-document/SKILL.md`（`tools/office_io.py`）を呼び出す。
7. **完了の報告**:
   - ファイルの書き出し・更新が完了した事実と、保存したファイルパスのみを簡潔に報告する（ファイル本文をチャットへ再掲しない）。

## 書き出しに失敗した場合（上限と行き先）

- **同一ファイルへの書き出し試行は3回まで**とする。3回失敗した場合は、それ以上繰り返さず打ち切る。
- 打ち切ったら、**Product Ownerへエスカレーション**し、以下を報告して指示を仰ぐ。
  - 対象ファイルのパス / 失敗した操作 / エラーの内容 / 書き出せていない章の範囲
- Step 5の検証で崩れを検出した場合、**修正の試行も3回まで**とする。3回で直らない場合は、崩れている箇所（ファイルパスと行番号）を明示して報告する。**崩れたまま「完了」と報告してはならない。**

## 禁止事項

- **虚偽の完了報告の禁止**: 実際には書き出せていない、または崩れが残っている状態で「完了」と報告してはならない。Step 5の読み直しを省略することも禁止する。
- **無検証の全文上書きの禁止**: 既存ファイルを、変更前の内容を確認せずに全文上書きしてはならない。
- **保存先の逸脱の禁止**: 開発成果文書を `docs/artifacts/` 以外へ保存してはならない。パスを自分の判断で変更することも禁止する。
- **仕様の勝手な創作の禁止**: 本スキルの役割は、作成者ペルソナが決定した仕様を正確にファイルへ反映することである。仕様の不足に気づいた場合は、推測で空欄を埋めずに作成者ペルソナへ差し戻す（ただし、作成者ペルソナが `JP-Humanizer` スキルを用いて元の意味を保持したまま自然な日本語へ推敲する作業は正規の手順である）。
- **スケルトンの残骸を残す禁止**: 【AIへの指示】コメント、記入例（`*-EX`）、未記入のプレースホルダを成果文書に残したまま完了としてはならない。
- **チャットへの全文再掲の禁止**: 書き出した内容をチャットへ貼り直してはならない。報告はファイルパスと完了の事実のみとする。
