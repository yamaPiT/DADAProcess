# コンテキスト・リセット (Context Reset)

## 発動条件 (Trigger)
- `dada-process` スキルの各工程における「承認ゲート」（承認ゲート型）または「自律ゲート」（自律型）を通過した直後。
- Product Ownerから「承認します」「次へ進んで」等の許可が出た直後（承認ゲート型）。

## 実行手順 (Mechanical How)

### Step 1: サマリーの保存（方式によらず必ず実行）
`docs/process/last_phase_summary.md` の全文を、以下のテンプレートの構造どおりに上書きする（見出しの追加・省略をしない）。

   ```markdown
   # フェーズ移行サマリー (Last Phase Summary)

   > 本ファイルは `context-reset` スキルにより、フェーズ移行時に自動的に上書きされます。
   > 新しいコンテキストで作業を開始するAIエージェントは、まず本ファイルを読み込んで前回の文脈を復元してください。

   ## 完了フェーズ
   - **Phase**: Phase 1 - 要求定義（例）
   - **完了日時**: 2026-XX-XX
   - **承認者**: Product Owner / 自律ゲート（事前委譲）

   ## 次フェーズ
   - **Phase**: Phase 2 - 総合テスト仕様策定（例）
   - **着手指示**: SW105を入力としてSWP6（1〜4章）を作成する（例）

   ## 承認済みドキュメント一覧
   | ドキュメントID | ファイルパス | 状態 |
   | :--- | :--- | :--- |
   | SW105 | `docs/artifacts/SW105_ソフトウェア要求仕様書.md` | 承認済 / 未作成 |
   | SWP6 | `docs/artifacts/SWP6_ソフトウェア総合テスト仕様書・報告書.md` | 未作成 / 計画承認済 / 報告書承認済 |
   | SW205 | `docs/artifacts/SW205_ソフトウェアアーキテクチャ設計書.md` | 承認済 / 未作成 |

   ## 引き継ぎ事項・注意点
   - **開発対象**: 従来型プログラム / エージェント定義（`.agents/AGENTS.md` 第9節。エージェント定義の場合は `docs/guidelines/agent_design_principles.md` と `docs/templates/agent/` を参照すること）
   - **実行モード**: 承認ゲート型 / 自律型（`.agents/AGENTS.md` 第10節。自律型の場合は `docs/process/autoloop_log.md` に記録しながら進めること）
   - **動作モード**: モードX / モードY（実行環境で自動判定。チャットで選ぶものではない）
   - **スケール判定**: Hotfix / Minor / Major（理由: ～）
   - **実行プロファイル**: Guided / Autonomous（`.agents/AGENTS.md` 第4節）
   - **機械チェックの状態**: （`dada_check.py` の最終要約行。未実行の場合はその理由）
   - **Product Ownerからの特別な指示**: （なければ「なし」）
   - **未解決のTBD・技術的リスク**: （なければ「なし」）
   - **次フェーズで注意すべきポイント**: （なければ「なし」）
   ```

- **書き出し前に必ず `python tools/dada_check.py all --summary` を実行**し、その要約行を「機械チェックの状態」へ転記する。次フェーズのエージェントは、この1行だけで承認済み文書の健全性を把握できる（文書を読み直す必要がない）。Phase 4完了時は続けて `python tools/dada_check.py report --summary` の要約も転記する。
- SWP6の状態は3値のみ使う。Phase 2完了時は **計画承認済**、Phase 4完了時は **報告書承認済**。`承認済` の1語では計画と報告書を区別できないため使わない。

### Step 2: 環境と実行モードの判定（方式の選択）

サマリー保存後、**①自分が使用できるツール一覧にサブエージェント起動ツール（`invoke_subagent` 等）が存在するか ②実行モードが承認ゲート型か自律型か**の2点を確認し、方式を選択する。

| サブエージェント起動 | 実行モード | 採用する方式 |
| :--- | :--- | :--- |
| 可能（Antigravity 2.0 / CLI）＝**モードX（推奨）** | 承認ゲート型・自律型のいずれも | **方式A（サブエージェントによる自律リセット）** |
| 不可（Antigravity IDE / v1 / その他）＝**モードY** | 承認ゲート型 | **方式B（手動リセット）** |
| 不可（Antigravity IDE / v1 / その他）＝**モードY** | 自律型 | **方式C（自律連続実行）** |

- 判定に迷う場合（製品名が不明な場合）は、**ツールの有無を唯一の判定基準**とする: サブエージェント起動ツールがあれば方式A（モードX）。
- **方式Aが最も汚染に強い。** サブエージェントが使えるなら、実行モードによらず方式Aを選ぶこと（＝モードXを優先する）。
- 方式Bに切り替える際、Product Ownerに「この環境ではサブエージェントを起動できないため、お手数ですが新しい会話の開始をお願いします」と理由を添えること。
- 方式Cは、人間の操作を待たずに完走するために方式Bの代替として用いる。**実行モードが承認ゲート型のときに方式Cを選ぶことを禁止する**（承認ゲートを飛ばすことになるため）。

### Step 3: リセットの実行

**方式A: サブエージェントによる自律リセット（Antigravity 2.0 / CLI）**
人間の操作を介さずに以下を実行する。

1. 「未確定な議論を破棄し、次フェーズをクリーンなコンテキストで開始します」と宣言する。
2. 次Phaseの作業を担当する**サブエージェントを新規に起動**する。サブエージェントへの指示は、以下の情報**のみ**で構成すること。
   - 適用するペルソナスキルのパス（例: `.agents/skills/test-engineer/SKILL.md`）
   - `docs/process/last_phase_summary.md` を最初に読むこと
   - 入力となる承認済みドキュメントのパスと、成果物の出力先パス
   - Product Ownerからの明示的な指示（あれば原文のまま）
3. **【厳守】現在の会話のチャット履歴・議論の要約・未承認の推測をサブエージェントへ渡してはならない。** 承認済みドキュメントとサマリーだけが唯一の引き継ぎ情報である。
4. メイン会話（オーケストレーター）は、サブエージェントの完了報告と承認ゲートの仲介のみを行う。

**方式B: 手動リセット（Antigravity IDE / v1）**
サブエージェントを起動できない環境では、従来どおり人間に依頼する。

1. 「未確定な議論をメモリから消去します」と宣言する。
2. Product Ownerに「この環境ではサブエージェントを起動できないため、新しいチャットウィンドウを開いて指示をください」と依頼する。
3. 新しい会話側のエージェントは、`dada-process` スキルの「起動時の状態判定」に従い、`last_phase_summary.md` から文脈を復元して次フェーズを開始する。

**方式C: 自律連続実行（サブエージェント不可の環境で、実行モードが自律型の場合）**
人間の操作を待たずに同一会話内で次フェーズへ進む。**物理的なコンテキスト分離ができないため、論理的なリセットで代替する**（下記の限界を理解して使うこと）。

1. 以下の宣言を、省略せずそのまま出力する。

   > [論理リセット] これまでのチャット履歴に含まれる議論・推測・未承認の判断を、以降の情報源から除外します。以降参照するのは次の3点のみです。
   > 1. `docs/process/last_phase_summary.md`
   > 2. サマリーの「承認済みドキュメント一覧」に記載されたファイル
   > 3. Product Ownerが明示した指示の原文

2. `docs/process/last_phase_summary.md` を**改めて読み直す**（記憶で代用しない）。
3. サマリーに記載された承認済みドキュメントを、必要な範囲で読み直す。
4. 次Phaseのペルソナスキルを読み込み、そのペルソナを適用して作業を開始する。
5. **限界の自覚**: 方式Cでは過去の会話履歴が物理的に残る。したがって、次フェーズの作業中に「先ほど話した通り」「前に決めたように」という形で履歴を根拠にすることを**禁止**する。根拠にできるのは、上記1で列挙した3点に書かれている内容のみである。判断の根拠を述べるときは、必ずファイルパスまたはIDで示すこと。

## 禁止事項
- サマリーに**チャット内の未承認の議論・推測を「決定事項」として書かない**こと。書いてよいのは、承認済みドキュメントの状態と、Product Ownerが明示した指示のみ。
- 方式Aにおいて、リセットの体裁を取りながら**メイン会話の文脈をサブエージェントに流し込む**こと（要約の受け渡し等）を禁止する。
- 方式Cにおいて、論理リセットの宣言をしたのに**チャット履歴を根拠に判断する**ことを禁止する（宣言だけして実質的に汚染を持ち込む行為である）。
- **実行モードが承認ゲート型のときに方式Cを選ぶこと**を禁止する。承認ゲートを飛ばすプロセス違反にあたる。
