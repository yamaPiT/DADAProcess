# コンテキスト・リセット (Context Reset)

## 1. 発動条件と思考過程
`dada-process` の承認ゲート・自律ゲート通過直後に発動する。開始・完了時に思考過程（①現在地 ②判断の根拠 ③次の一手）と末尾進行表示1行を出力する。

## 2. 実行手順

### Step 1: サマリーの保存（全方式共通）
書き出し前に `python tools/dada_verify.py --summary`（または `python tools/dada_check.py all --summary`、Phase 4 完了時は `python tools/dada_check.py report --summary`）を実行し要約行を得る。その後 `docs/process/last_phase_summary.md` を以下の形式で上書きする（`SWP6` 状態は `未作成` / `計画承認済` / `報告書承認済` の3値のみ）。

```markdown
# フェーズ移行サマリー (Last Phase Summary)

## 完了フェーズ
- **Phase**: Phase N - フェーズ名
- **完了日時**: YYYY-MM-DD
- **承認者**: Product Owner / 自律ゲート（事前委譲）

## 次フェーズ
- **Phase**: Phase M - 次フェーズ名
- **着手指示**: 承認済み文書を入力として次成果物を作成する

## 承認済みドキュメント一覧
| ID | ファイルパス | 状態 |
| :--- | :--- | :--- |
| SW105 | `docs/artifacts/SW105_ソフトウェア要求仕様書.md` | 承認済 / 未作成 |
| SWP6 | `docs/artifacts/SWP6_ソフトウェア総合テスト仕様書・報告書.md` | 未作成 / 計画承認済 / 報告書承認済 |
| SW205 | `docs/artifacts/SW205_ソフトウェアアーキテクチャ設計書.md` | 承認済 / 未作成 |

## 引き継ぎ事項・注意点
- **開発対象**: 従来型プログラム / エージェント定義
- **実行モード**: 承認ゲート型 / 自律型
- **動作モード**: ツール自動作成 / 人間作成
- **スケール判定**: Hotfix / Minor / Major（理由: ～）
- **実行プロファイル**: Guided / Autonomous
- **機械チェックの状態**: （要約行。未実行時は理由）
- **Product Ownerからの特別な指示**: （なければ「なし」）
- **未解決のTBD・技術的リスク**: （なければ「なし」）
- **次フェーズで注意すべきポイント**: （なければ「なし」）
```

### Step 2: リセット方式の選択と実行
`invoke_subagent` 等の有無と実行モードで方式を決める。

| サブエージェント自動作成 | 実行モード | 採用方式 |
| :--- | :--- | :--- |
| 可能（`invoke_subagent` あり） | 承認ゲート型・自律型共通 | **方式A（サブエージェント自律リセット・推奨）** |
| 不可（IDE / 非対応環境） | 承認ゲート型 | **方式B（手動リセット）** |
| 不可（IDE / 非対応環境） | 自律型 | **方式C（論理リセット連続実行）** |

- **方式A**: 「未確定な議論を破棄し、次フェーズをクリーンなコンテキストで開始します」と宣言し新規サブエージェントを起動する。渡すのは **(1) 適用スキルパス (2) `docs/process/last_phase_summary.md` 読込指示 (3) 承認済み文書と出力先パス (4) PO指示原文** のみ。
- **方式B**: 「未確定な議論をメモリから消去します」と宣言し、Product Owner に新規チャットでの再開を依頼して終了する。
- **方式C**: 「[論理リセット] 会話履歴の議論・推測を除外し、`docs/process/last_phase_summary.md`・承認済み文書・PO指示原文のみを参照します」と宣言して文書を読み直し次スキルへ移る。

## 3. 禁止事項・自己チェック
- サマリーへの未承認推測記載、方式Aでの履歴要約渡し、承認ゲート型での方式C選択、方式Cでの履歴根拠判断を禁止する。
- [ ] `docs/process/last_phase_summary.md` 更新と方式A/B/Cの正しい実行を確認したか
