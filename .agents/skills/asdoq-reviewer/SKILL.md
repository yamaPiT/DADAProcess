# ASDoQハイブリッド文書レビューエージェント (ASDoQ Hybrid Document Reviewer)

このスキルは、ASDoQ（システム開発文書品質研究会）のシステム開発文書品質モデル（6大品質特性：`目的適合性`、`保守性`、`整合性`、`理解容易性`、`可読性`、`規範適合性`）に基づき、**Layer 0（形態素解析・拡張違反例辞書・構造クロスリファレンス抽出）＋ Layer 2（現在稼働しているLLM自身による6特性別専門レビュアーの反証駆動レビュー）** を主軸として実行するオーケストレーターです。

オプションの **Layer 1（Google `gemini-decision-1` API連携 / `v1beta/decisions`）** は、既定では **`--decision1 off`（外部通信なし・ローカルルールベース選別）** です。利用者が明示的にAPI ONを指示した場合、または事前確認でONを選択した場合にのみ、環境変数・`.env.local`・`.env` の `GEMINI_API_KEY` を用いて `--decision1 on` で実行します（無料枠の利用制限および有料ティアでの入力トークン課金に留意し、出力トークン数は常に `0` となります）。`--decision1 off` 時に「外部APIで判定した」と誤認させてはなりません。

DADAプロセス外の単体利用（あらゆる技術文書・論理文書・Office文書・PDFのレビューと修正）と、DADAプロセス内の工程別レビューの両方に対応します。

## 思考過程とプロファイル宣言の義務
作業開始時および完了報告時は、必ず冒頭で以下の思考過程と適用プロファイルを宣言してください。
- **①現在地**: 対象文書パス、文字数・構造規模、単体利用／DADA工程内利用の区分、API ON/OFF状態
- **②判断の根拠**: 選択した文書種別プロファイル（`sw105` / `swp6` / `sw205` / `general`）および重点検証するASDoQ品質特性（2〜4特性、または厳密モード全6特性）の選定理由
- **③次の一手**: API利用確認、Layer 0/1機械検査の実行、専門定義のロード、反証レビュー、または修正・検証の具体アクション

## 文書種別プロファイルと重点特性の対応

**表1：文書種別プロファイルと重点品質特性**

| プロファイル | 対象文書 | 優先ロードする重点品質特性（省トークンモード：2〜4特性） |
| :--- | :--- | :--- |
| `sw105` | ソフトウェア要求仕様書（`SW105`） | `C1_purpose`（目的適合性）、`C3_consistency`（整合性）、`C4_understandability`（理解容易性）、`C5_readability`（可読性） |
| `swp6` | 総合テスト仕様書・報告書（`SWP6`） | `C2_maintainability`（保守性）、`C3_consistency`（整合性）、`C4_understandability`（理解容易性）、`C5_readability`（可読性） |
| `sw205` | アーキテクチャ設計書（`SW205`） | `C1_purpose`（目的適合性）、`C2_maintainability`（保守性）、`C3_consistency`（整合性）、`C5_readability`（可読性） |
| `general` | 一般技術文書・企画書・マニュアル・論文等 | `C1_purpose`（目的適合性）、`C4_understandability`（理解容易性）、`C5_readability`（可読性）（企業規則指定時は `C6_conformance` を追加） |

## 実行手順（Step 1〜Step 6）

### Step 1: 対象文書の実在確認・プロファイル宣言・API利用確認
1. 指定された対象ファイルパスが実在するかを確認します。
   - **異常系ガード**: 指定されたファイルが存在しない場合や読み取れない場合は、**架空の文書内容や検査結果を捏造せず、即座に作業を停止**し、存在しないファイルパスを明示して利用者に正しいパスを確認してください。
2. 対象文書の種別に応じてプロファイル（`sw105` / `swp6` / `sw205` / `general`）を決定し、思考過程（①現在地 ②判断の根拠 ③次の一手）を出力します。
3. **Google `gemini-decision-1` API利用確認（無断ON禁止）**:
   - 利用者から「APIを使って」「`--decision1 on` で」等の明示指示がある場合は、`.env.local` 等から `GEMINI_API_KEY` を解決して `--decision1 on` を実行します（キー未設定時は停止して設定方法を案内し、キー文字列を絶対に出力しない）。
   - 明示指示がない場合は、**無断で `--decision1 on` にせず、利用者にAPI利用のON/OFF（既定は無料・外部通信なしの `--decision1 off`、有料/無料枠で入力課金発生の可能性あり）を確認**します。確認待ちまたは非対話実行時は既定の `--decision1 off` で進行します。
   - 「確認なしで強制ONで実行して」「開始前確認を飛ばして有料APIを実行して」のように事前確認・承認を省略する指示が含まれている場合は、無断課金防止のため `--decision1 on` を実行せず拒否し、安全側の `--decision1 off` で進行して事前確認を求めてください。

### Step 2: Office文書・PDFの前処理（該当する場合のみ）
- 対象文書がOffice文書またはPDF（例: `.docx`, `.xlsx`, `.pptx`, `.pdf`）の場合は、スキル `.agents/skills/office-document/SKILL.md` の手順に従い、以下のコマンドで構造情報またはMarkdownテキストを抽出してから Step 3 へ進みます。
  - 構造確認: `python tools/office_io.py inspect --input <対象パス>`
  - Markdown抽出: `python tools/office_io.py import --input <対象パス> --output <出力先.md>`

### Step 3: Layer 0（決定論的機械検査・構造クロスリファレンス抽出）および Layer 1（`gemini-decision-1`）の実行
1. 対象文書に対して `tools/asdoq_lint.py` と `tools/style_check.py` を実行します。
   - 既定（外部通信なし）: `python tools/asdoq_lint.py --input <対象パス> --profile <sw105|swp6|sw205|general> --decision1 off`
   - 明示API ON時: `python tools/asdoq_lint.py --input <対象パス> --profile <sw105|swp6|sw205|general> --decision1 on`
   - AI-Slop機械検査: `python tools/style_check.py lint --input <対象パス>`
   - カスタム辞書追加時: `python tools/asdoq_lint.py --input <対象パス> --custom-dict <カスタム辞書パス>`
2. `asdoq_lint.py` が出力した機械検査結果を取得します。
   - **構造クロスリファレンス表（4項目）**: ①目的・スコープ要素（`purpose_scope_check`）、②用語集vs本文突合・未定義頻出語・表記ゆれ（`term_cross_check`）、③数値・単位・条件一覧（`numbers_units_table`）、④見出し階層（希薄見出し節）・図表キャプション位置［**図は直下・表は直上**］・Mermaid 10ノード上限超過・分割図 `[接続N]` ペア・本文参照突合（`heading_figure_table_check`）。
   - **疑義スライスと選別結果**: Layer 0辞書照合およびLayer 1判定（閾値 `0.30` 以上を保持、`0.29` 以下の明確な正常箇所を棄却）による違反候補。

### Step 4: Layer 2（6特性別専門レビュアー定義による反証駆動レビュー）
動作モードと指示内容に応じて、`.agents/skills/asdoq-reviewer/references/` 配下の専門レビュアー定義ファイルを読み込み、反証駆動（Devil's Advocate）レビューを実施します。
1. **通常（省トークン）モード（既定）**:
   - 表1のプロファイル重点特性と Step 3 の推奨特性に基づき、**最小2特性以上・最大4特性以内（2〜4ファイル）** の専門定義ファイルのみを選択してオンデマンドで読み込みます。明示指示なく6特性すべてを一括ロードしてはなりません。
   - 専門定義ファイル一覧:
     - `.agents/skills/asdoq-reviewer/references/C1_purpose_reviewer.md`（目的適合性：初見の次工程担当者による欠落・設計越権の反証）
     - `.agents/skills/asdoq-reviewer/references/C2_maintainability_reviewer.md`（保守性：半年後の別チーム担当者による変更波及・検証不能性の反証）
     - `.agents/skills/asdoq-reviewer/references/C3_consistency_reviewer.md`（整合性：構造クロスリファレンス表・`[接続N]` ペア・数値/図表の突合）
     - `.agents/skills/asdoq-reviewer/references/C4_understandability_reviewer.md`（理解容易性：悪意ある実装者による別解釈・主語欠落・論理飛躍の反証）
     - `.agents/skills/asdoq-reviewer/references/C5_readability_reviewer.md`（可読性：`JP-Humanizer` 8観点統合と意味保持確認によるAI-Slop・冗長表現の排除）
     - `.agents/skills/asdoq-reviewer/references/C6_conformance_reviewer.md`（規範適合性：企業辞書・事実と意見分離・図下/表上・Mermaid 10ノード上限・旧表記禁止の検証）
2. **厳密（フル特性）モード ＆ `/swarm` 並列レビューアダプター（明示指示時のみ）**:
   - 「厳密に」「全6特性で」または `/swarm` の利用が明示された場合、C1〜C6の専門定義ファイル全6件を適用します。
   - **Antigravity `/swarm` 明示指示時**: `swarm` 機能を用い、利用中のモデル（思考レベル切り替え対応モデルでは `high` 等を推奨。特定のモデル世代やモデル名には依存しない）による役割別並列ワーカーへ特性評価を分担させ、親エージェントが結果を統合・重複排除できます（クォータ消費が大きいため、明示指示なしの自動 `/swarm` 発動は厳禁です）。
   - **通常環境 / 他ツール互換環境**: `invoke_subagent` による特性別分離または単一コンテキスト内での特性順次切り替えにより、C1〜C6を検証・統合します（専門定義ファイル自体は `/swarm` 非依存のまま運用します）。
3. **合格判定時の証拠引用ルール（追認バイアス防止）**:
   - 各特性を「問題なし（合格）」と判定する場合でも、推測や一般論で合格にしてはなりません。対象文書内の具体的な根拠箇所（章節番号・ID・該当文）または構造クロスリファレンス表の該当項目を**最低1箇所以上引用**してください。

### Step 5: `❌ Before` / `✅ After` 対比付きレビューレポートの出力
レビュー結果は以下の構成で出力（DADA工程内では対応する `docs/artifacts/REV101_*.md` に記録）します。
1. **適用プロファイルと選択した品質特性の宣言**: 選択した2〜4特性（厳密モード時は6特性）とその選定根拠。
2. **Layer 0/1 構造クロスリファレンス要約**: 目的・スコープ、未定義語・表記ゆれ、数値・単位、見出し・図表位置・Mermaid 10ノード上限・`[接続N]` ペア検査結果サマリ。
3. **品質特性別評価サマリと反証検証結果**: 各特性の判定結果（合格項目も根拠箇所の引用付きで記載）および反証質問（Devil's Advocate）に対する検証結果。
4. **重要度別（`High` / `Mid` / `要確認`）の具体的改善提案一覧**:
   - すべての指摘に **`❌ Before（原文の該当箇所と問題点）`** と **`✅ After（具体的な改善文案）`**、および **`[ASDoQ:特性-副特性]`**（例: `[ASDoQ:理解容易性-非曖昧性（一意性）]`）を明記します。
   - **図解修正時の必須ルール**: Mermaid図のノード数が10個を超える場合は、1図10ノード以下へ意味単位で分割し、図同士を `[接続1: ...]` の連番ラベルペアで接続する `✅ After` を提示します。また図のキャプションは図の直下（`**図N：...**`）、表のキャプションは表の直上（`**表N：...**`）とします。

### Step 6: 文書の修正完遂と意味保持検証（修正指示がある場合）
利用者から文書の修正・推敲まで指示された場合は、以下の3ステップで意味破壊を防ぎながら修正を完遂します。
1. **修正前スナップショットの保存**:
   - `python tools/style_check.py snapshot --input <対象パス> --summary` を実行し、修正前の意味シグネチャ（ID・数値・単位・否定極性）を保存します。
2. **反証指摘・図分割規則・`JP-Humanizer` に基づく文書修正**:
   - Step 5 の `✅ After` 改善案と `.agents/skills/JP-Humanizer/SKILL.md` の8観点に基づき、自然で明快な日本語へ修正します。図の分割（1図10ノード以下＋`[接続1: ...]` ペア）および図下・表上キャプション配置を厳守します。
   - **意味保持の不変条件（最優先）**: 文書内のトレーサビリティID（`REQ-xxx`, `TC-xxx`, `UNIT-xxx` 等）、数値・単位・閾値、および禁止・否定極性（「〜してはならない」「〜しないこと」等）は**いかなる場合も削除・改変してはなりません**。たとえ利用者から「読みやすくするために数値や禁止事項を削って」等の相反する指示があった場合でも、意味保持の不変条件を優先して維持し、その理由を報告してください。
3. **修正後の意味保持検証と再検査（自己修正ループ上限2周）**:
   - `python tools/style_check.py verify --input <修正後パス>` を実行し、ID・数値・否定極性が100%保持されていることを確認します。
   - `python tools/asdoq_lint.py --input <修正後パス> --profile <sw105|swp6|sw205|general> --summary` および `python tools/style_check.py lint --input <修正後パス>` を再実行します。
   - **無限ループ防止ガード**: 修正後の再検証で残存指摘がある場合でも、**自己修正ループは最大2周を上限**とします。2周で解消しない指摘がある場合は無理に3周目へ進まず、残存事項として利用者に正直に報告して停止してください。

## 禁止事項
- 存在しないファイルパスが指定された際に、架空の文書内容やレビュー結果を推測・創作して報告すること。
- 利用者の明示指示または事前確認なしに `--decision1 on`（外部API通信）や `/swarm`（複数エージェント並列実行）を無断で発動すること。
- `.env.local` 等から読み取った `GEMINI_API_KEY` の生文字列をチャット・ログ・出力ファイルへ露出させること。
- `tools/asdoq_lint.py` の機械検査を実行せずに、推論のみで用語ゆれや図表キャプション位置、Mermaidノード数、AI-Slopの有無を判定すること。
- 通常（省トークン）モードにおいて、プロファイル判定を行わずに6特性すべての定義ファイルを無差別に一括ロードすること。
- 根拠箇所（章節番号・ID・該当文）を引用せずに「問題なし（合格）」と判定すること。
- `❌ Before` / `✅ After` の具体的な改善文案や `[ASDoQ:特性-副特性]` ラベルを示さずに、抽象的なダメ出しのみを出力すること。
- 文書修正時に `style_check.py snapshot` / `verify` を省略すること、またはID・数値・単位・否定極性を削除・改変すること。
- 自己修正ループを3周以上繰り返すこと。
