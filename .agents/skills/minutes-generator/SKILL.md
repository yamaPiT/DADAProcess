# 議事録生成スキル (Minutes Generator)

本スキルは、会議メモテキストから高品質なMarkdown形式の議事録を構造化して作成・保存し、機械検証を経て完了報告を行うための標準スキルです。
対応機能ID（トレーサビリティ）：UNIT-001, REQ-002, REQ-003, REQ-006

## 1. 概要と役割
エージェントは本スキルを実行する際、以下の3つの要素に従って動作します。
- **入力会議メモ**: `docs/<FileName>.txt`
- **議事録ひな形知識**: `references/minutes_template.md`（UNIT-002）
- **構文検証ツール**: `tools/verify_minutes.py`（UNIT-003）
- **出力成果物**: `docs/artifacts/<FileName>_議事録.md`

## 2. 作業手順（Prompt Chaining）

以下のステップを順番に実行してください。

### ステップ1: 入力パスの検証
1. 利用者から指示されたファイルパスを確認します。
2. 以下の検証コマンドを実行して入力パスの形式とファイルの実在性を検査します。
   `python tools/verify_minutes.py check-input docs/<FileName>.txt`
3. 終了コードに応じた分岐を行います:
   - **終了コード0**: ステップ2へ進む。
   - **終了コード2**: 入力エラーです。直ちに処理を中断し、ツールの出力メッセージ（例:「入力ファイルが見つかりません: <パス>」または「入力パスは docs/<FileName>.txt 形式で指定してください」）を利用者に報告して終了します。推測で処理を続行してはなりません。

### ステップ2: 会議メモの解析と空ファイル判定
1. `docs/<FileName>.txt` の内容を読み込みます。
2. ファイル内容が0バイトまたは空文字列の場合、議事録ファイルの生成を行わず、「入力ファイルの内容が空です」と利用者に報告して処理を終了します。
3. 空でない場合、ひな形ファイル `references/minutes_template.md` を読み込みます。
4. 【思考過程の強制】会議メモから以下の5要素を抽出・分類して整理します:
   - **会議概要**: 日時（YYYY-MM-DD形式）、場所、出席者、目的
   - **決定事項**: 会議で正式に合意された決定事項（合意がない場合は「決定事項なし」）
   - **討議内容**: 議題ごとの論点、発言要約、結論
   - **TODO一覧**: 実行課題（アクションアイテム）のタスク内容、担当者、期限
     - ※担当者または期限が未決定の場合は「未定」を設定する
     - ※決定事項とTODOを混同せず、実行アクションのみをTODO表に配置する
   - **次回議題**: 次回検討事項（ない場合は「なし」）

### ステップ3: 議事録Markdownの生成と保存
1. `references/minutes_template.md` のひな形構造に従い、Markdownテキストを整形します。
   - 以下の6つの必須見出しを必ず含めます:
     - `# 会議議事録`
     - `## 1. 会議概要`
     - `## 2. 決定事項`
     - `## 3. 討議内容`
     - `## 4. TODO一覧`
     - `## 5. 次回議題`
   - 日付は必ず `YYYY-MM-DD` 形式で記述します。
   - TODO一覧は `タスク内容`、`担当者`、`期限` の3列表とします。
2. 出力先ディレクトリ `docs/artifacts/` の存在を確認し、存在しない場合は作成します。
3. `docs/artifacts/<FileName>_議事録.md` にUTF-8形式で書き出します。

### ステップ4: 構文検証と自己校正ループ
1. 生成した議事録ファイルに対して以下の検証コマンドを実行します。
   `python tools/verify_minutes.py check-output docs/artifacts/<FileName>_議事録.md`
2. 終了コードに応じた分岐を行います:
   - **終了コード0（合格）**: ステップ5へ進む。
   - **終了コード1（不合格）**:
     - 欠落している必須見出しまたは不正な日付書式を修正し、ファイルを再保存して再検証コマンドを実行します。
     - **ループ上限**: この修正ループは**最大2回まで**繰り返します。2回試行しても終了コード0にならない場合はループを打ち切り、未解決状態と欠落見出し名・エラー内容を利用者へ報告して処理を中断します。
   - **終了コード2（実行エラー）**:
     - ファイル保存に失敗しているか重大なパス異常です。直ちに処理を中断し、エラー内容を利用者に報告します。

### ステップ5: 完了報告（二重出力の禁止）
1. 議事録本文の全文は成果物ファイル `docs/artifacts/<FileName>_議事録.md` にのみ書き込みます。
2. 会話スレッドには、**本文の全文を再掲せず**、以下の要約情報のみを出力して完了報告を行います:
   - 保存先ファイルパス: `docs/artifacts/<FileName>_議事録.md`
   - 構文検証結果: 検証合格
   - 未確定TODO件数（次回確認対象）: 担当者または期限が「未定」となっているTODOの件数（0件の場合は「未確定TODO: 0件」と明記）

## 3. 禁止事項（ポカヨケ）
- **二重出力の禁止**: 会話スレッドに議事録本文の全体または主要な節を再掲してはならない。チャットには保存先パスと要約のみを出力すること。
- **架空情報の創作禁止（幻覚防止）**: 会議メモに存在しない人物名、発言、決定事項、日付を推測・創作して出力してはならない。
- **未定項目の推測埋め込み禁止**: 担当者や期限が不明なタスクに対して、推測で日付や人物名を割り当ててはならない。必ず「未定」と記載すること。
- **決定事項とTODOの混同禁止**: 会議の合意事項をTODO一覧に含めたり、アクションアイテムを決定事項に混入させてはならない。
- **必須見出しの省略・改変禁止**: 定義された6大見出しの文字列や階層を変更・省略してはならない。
- **日付書式の改変禁止**: `YYYY/MM/DD` や `YYYY年MM月DD日` などの書式を使用してはならない。必ず `YYYY-MM-DD` 形式を維持すること。
- **無制限ループの禁止**: 構文検証失敗時の修正ループは最大2回までとし、上限に達した場合は必ず打ち切って利用者に報告すること。

## 4. 完了前のチェックリスト
完了報告を行う前に、以下の全項目を確認してください。
- [ ] 入力パス検証（`check-input`）が終了コード0で通過したこと
- [ ] 会議メモが空ファイルの場合、議事録生成を行わずに中断報告したこと
- [ ] 生成した議事録に6大必須見出しがすべて含まれていること
- [ ] 日付書式がすべて `YYYY-MM-DD` 形式であること
- [ ] TODO表に「タスク内容」「担当者」「期限」の3列が存在し、未確定項目には「未定」が記載されていること
- [ ] 議事録検証ツール（`check-output`）の終了コードが0であること
- [ ] 会話スレッドに議事録本文全文を再掲せず、保存先パス・検証合格・未確定TODO件数の要約のみを報告していること
