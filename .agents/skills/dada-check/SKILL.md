# 機械チェックの実行 (DADA Check)

本スキルは、DADAプロセスの各フェーズで必要になる**網羅的な機械作業**を、AIの推論からスクリプトへ移すための手順です。

## なぜスクリプトに任せるのか
「全REQ-IDに対応するTC-IDがあるか」のような照合をAIが記憶と推論で行うと、件数が増えるほど取りこぼしが発生し、最悪の場合「確認したつもり」の虚偽報告になります。スクリプトは取りこぼしません。
また、照合のために文書を全文読み込む必要がなくなるため、トークン消費も下がります。**AIは機械が判定できない本質的な検証（要求の妥当性・テストの十分性・設計の適切さ）に思考を集中してください。**

## 発動条件 (Trigger)
- 作成者スキル（`requirements-engineer` / `test-engineer` / `architect` / `programmer`）が「完了前の自己チェック」を行うとき。
- レビュアースキル（`requirements-reviewer` / `test-reviewer` / `architecture-reviewer` / `code-reviewer`）がレビューを開始するとき。
- 承認ゲートでProduct Ownerへ報告する直前。

## 実行手順 (Mechanical How)

### Step 1: コマンドを実行する
リポジトリのルートで、以下のいずれかを実行する。

```bash
python tools/dada_check.py all
```

- `python` が見つからない場合は `python3 tools/dada_check.py all`、次に `py -3 tools/dada_check.py all` を試す。
- 特定のチェックだけ実行する場合の引数は `trace`（ID対応）/ `lint`（文書の書き方）/ `code`（コードとの対応）/ `status`（帳票の未解決）。
- 結果は標準出力に表示され、同じ内容が `docs/process/check_report.md` に保存される。

### Step 2: 結果を読む
出力の最終行が要約である。

```
DADA-CHECK: NG（High指摘あり） | High 3 / Mid 5 / 要確認 2 | 対象: SW105, SWP6
```

| 重要度 | 意味 | 対応 |
| :--- | :--- | :--- |
| **High** | 後工程を開始できない欠陥 | 必ず解消する。解消できない場合は残課題としてProduct Ownerに明示報告する |
| **Mid** | 品質を損なうが工程は進められる | 原則として解消する |
| **要確認** | 機械では判定できない | 妥当性を自分で判断し、対応または「問題なし」の判断理由を述べる |

### Step 3: 指摘を処理する
- **自分が作成者ペルソナの場合**: High・Midの指摘を修正し、修正後にStep 1を再実行して解消を確認する。
- **自分がレビュアーペルソナの場合**: 機械チェックの結果を自分の指摘としてレビュー記録表（`REV101_*.md`）またはバグ管理表（`BUG101`）へ転記する。**そのうえで、機械では検出できない観点（下記）を人間の目で検証する。**

### Step 4: 機械チェックでは検出できない観点を自分で検証する（省略禁止）
スクリプトが「OK」でも、以下は必ずAI自身が判断すること。スクリプトは形式を見るだけで、**内容の妥当性は見ていない**。

| 観点 | 例 |
| :--- | :--- |
| 要求の妥当性 | 検証条件の数値が書かれていても、その数値がProduct Ownerの意図と合っているか |
| テストの十分性 | TC-IDが存在しても、そのテストが要求の本質的なリスクを突いているか |
| 設計の適切さ | 循環依存がなくても、責務の分割が保守可能な粒度か |
| 用語の一貫性 | 同じ概念に別名が使われていないか（機械では概念の同一性を判定できない） |
| 論理の矛盾 | 要求間・条件間に両立しない記述がないか |

### Step 5: 報告に結果を含める
承認ゲートやレビュー完了の報告に、機械チェックの要約1行を必ず含める。**指摘の全文をチャットへ再掲しない**（レポートファイルとレビュー記録表に記録済みであるため）。

## ツールを実行できなかった場合
- Pythonが利用できない、コマンドが失敗する等でスクリプトを実行できなかった場合は、各スキルに書かれた**手動の走査手順にフォールバック**する。
- そのうえで、**「機械チェックは未実行（理由: ～）。手動走査で代替した」と報告に明記する。**

## 禁止事項
- **虚偽報告の禁止**: 実行していないのに「機械チェック実行済み」と報告してはならない。報告には実際の要約行を貼ること。
- **鵜呑みの禁止**: 「要確認」の指摘を確認せずに無視してはならない。また、テンプレート指定時の目次差異のように正当な差異を欠陥として修正してはならない。
- **High指摘の隠蔽の禁止**: High指摘が残った状態で「問題なし」と報告してはならない。
- **結果の全文再掲の禁止**: レポート本文をチャットへ貼り直さない。パスと要約行のみを出力する。
