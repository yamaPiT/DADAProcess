# 外部調査スキル (Context7 MCP連携)

本スキルは、ローカル環境に存在しない最新のライブラリ仕様や公式APIドキュメントを、`context7` MCPサーバー経由で正確に取得する手順である。設計（Phase 3）や実装（Phase 4）での推測・ハルシネーションを防ぐために使用する。

## 実行手順 (Mechanical How)

1. **発動条件**:
   - アーキテクチャ設計（`architect`）での技術選定・インターフェース定義時、または実装（`programmer`）でのコード生成・セットアップ時に、「対象ライブラリの最新の公式仕様を確認する必要がある」と判断した場合に実行する。
2. **調査の実行**:
   - `context7` MCPサーバーのツール（ライブラリID解決およびドキュメント取得）を呼び出し、対象ライブラリ・フレームワークの公式ドキュメントを検索・取得する。
3. **一次情報の抽出（推測の排除）**:
   - 取得した一次情報（関数シグネチャ、設定項目、非推奨APIの有無、バージョン制約）のみを抽出し、古い学習知識や推測を混ぜずに呼び出し元のペルソナ（`architect` または `programmer`）へ引き渡す。
4. **出典とバージョンの明記**:
   - 引き渡す情報（および `SW205` のADR等に記録する根拠）には、取得元（ライブラリ名・バージョン・公式ドキュメントの該当箇所）を必ず添える。出典のない情報は後から検証できない。

## 取得できなかった場合（上限と行き先）

- **検索試行の上限は3回まで**とする。検索語を変えて再試行してよいのは3回目までとし、それ以上繰り返してはならない。
- 3回で目的の仕様が得られない場合は**調査を打ち切り**、以下を整理する。
  - 何を調べようとしたか / 試した検索語 / 確認できなかった仕様
- そのうえで、**推測で仕様をでっち上げずにProduct Ownerへエスカレーション**し、公式ドキュメントのURLやバージョンの提示を仰ぐ（または `SW205` に「要確認（推測）」と解消計画を明記する）。
- MCPサーバーが未設定・接続不能な場合は、1回目の失敗で即座に打ち切り、「context7が利用できないため未調査である」事実を明記する。

## 禁止事項

- **推測による代替の禁止**: 調査が失敗したことを隠し、不確かな学習知識や推測で埋めたAPI仕様を「公式仕様の確認結果」として扱ってはならない。
- **未調査の隠蔽の禁止**: 本スキルを実行していないのに「最新ドキュメントを確認済み」と報告してはならない。MCPサーバーが使えなかった場合は、その事実を明記する。
- **古い知識との混同の禁止**: 取得した公式ドキュメントの一次情報と、モデルの事前学習知識を混ぜて記述してはならない。
- **バージョンの取り違えの禁止**: 対象プロジェクトが指定しているバージョン（`SW105` の3.2節または `package.json` / `pyproject.toml` 等）と異なるメジャーバージョンの仕様を、断りなく適用してはならない。
- **無制限な再試行の禁止**: 上限3回を超えて検索を繰り返してはならない（時間とトークンを浪費するため）。
- **越権の禁止**: 本スキルの役割は公式情報の取得と受け渡しのみである。取得した情報をもとに独断で要求（`SW105`）や設計（`SW205`）を変更してはならない。
