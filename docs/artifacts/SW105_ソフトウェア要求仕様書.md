## 1. 概要

### 1.1 目的と位置づけ
本仕様書は、DADAプロセス v7.0 の省トークン化と高速化改訂に関する要求を定義する。想定する読み手は、Product Owner（マサ）、本プロセスを利用する開発者、および次工程のテスト・設計・実装を担当するAIエージェントである。配布範囲は、本リポジトリの利用者および切り出し機能で生成する4種類のスキルセット利用者とする。

現行の v6.1.0 では、常時読み込まれる憲法ファイルが約37.9 KBに達し、システム側で後半約13.9 KBが切り詰められる事象が発生している。さらに、複数ファイル間の記述重複や2段階の執筆・推敲手順、多回数のCLI検証により、トークン消費量と処理時間が増大している。本改訂の目的は、既存の品質保証を維持したまま、トークン使用量と処理時間を大幅に削減することである。維持する品質保証は、ASDoQ品質基準、JP-Humanizerによる日本語品質、自己校正、およびテストファーストの4点とする。

### 1.2 適用範囲
本改訂のスコープ内とスコープ外を明確に境界づける。

- **対象（スコープ内）**:
  - ワークスペース憲法（`.agents/AGENTS.md`）の圧縮と単一情報源化
  - ペルソナスキル群（`.agents/skills/` 配下）の軽量化、2度書き廃止、およびエージェント定義追加手順の分離
  - 決定論的機械検証ツールの1コマンド統合、重複検査の直交化、および現行個別CLIの後方互換維持
  - 4種類の単体スキルセット（`dada-core`、`office-suite`、`jp-humanizer`、`asdoq-reviewer`）と切り出しツール（`tools/export_skillset.py`）の維持
  - ポータブルコア層と Antigravity最適化アダプター層を分離する
  - `gemini-decision-1` 連携および `/swarm` 明示起動の互換性を維持する
  - 現行 v6.1.0（`main` ブランチ `ac2bf27`）との定量比較ベンチマーク検証ツールの構築
- **対象外（スコープ外）**:
  - Office文書変換エンジン（`tools/office_io.py`）の描画・パッチ機能の全面的な書き換え
  - ASDoQシステム開発文書品質モデル（6大品質特性および `tools/asdoq_dictionary.json` の品質基準自体）の改変
  - Phase 5（人間による動作評価と要求見直し）の自動化
  - 他社製AIツール（Claude Code、Cursor、Codex、GitHub Copilot）専用のプラグイン開発

### 3.2 ソフトウェア環境
プログラムレイヤーのスクリプトは、Windows PowerShell、macOS、および Linux 上の Python 3.8 以降で文字コード UTF-8 により動作しなければならない。改行コードは LF と CRLF の双方を許容する。`tools/` 配下の既存CLIスクリプト（5.3節の6本）は、既存サブコマンドと終了コード仕様（0=合格・1=指摘あり/未達・2=実行エラー）の後方互換を維持する。

文書品質基準は ASDoQ システム開発文書品質モデル Ver. 2.0a（ASDoQドキュメントライセンス ADL-1.1）に準拠する。日本語推敲観点と出典表記は『yomiyasu』（MIT License）のライセンス表示を引き継ぐ。開発文書ID（`SW105`・`SWP6`・`SW205`・`REV101_*`・`BUG101`・`TM101`）は変更しない。トレーサビリティID体系（`REQ-001`・`TC-001`・`UNIT-001`・`EV-001`・`R001`・`B001`）も現行から変更しない。

## 4. 機能要求

### 4.1 ユースケースとシナリオ
本改訂後の DADAプロセスには以下の4つの主要ユースケースがある。

1. **シナリオA（従来型プログラム開発）**: 開発者が「DADAプロセスで開発を開始してください。CSV集計CLIを作成します」と入力すると、オーケストレーターは Phase 0 で「従来型プログラム・承認ゲート型・Major」と判定する。各フェーズの作成役はエージェント定義用の差分手順を読み込まず、ベースライン比50%以下の指示書読込量で執筆と統合機械検証を完了する。
2. **シナリオB（エージェント定義開発とAntigravity最適化）**: 開発者が「DADAプロセスで開発を開始してください。開発対象はエージェント定義です」と入力した場合、システムはエージェント定義用の差分手順をオンデマンドで読み込む。Antigravity App 環境では、最適化アダプターに従いモデル使い分けや並列評価セット実行を活用できる。
3. **シナリオC（単体スキルと統合機械検証の実行）**: 開発者が「asdoq-reviewer スキル単体で仕様書をレビューして」または「JP-Humanizer スキル単体で推敲して」と指示すると、DADA工程を起動せず対象スキルのみで動作する。機械検証は統合機械検証CLIの1コマンドで完了し、外部API通信は `--decision1 on` の明示指定があった場合のみ実行する。
4. **シナリオD（ベースライン比較ベンチマーク検証）**: 開発者が比較ベンチマークツールを実行すると、ワークスペース内の憲法サイズ、フェーズ別読込バイト数、および標準ワークフロー上のCLI実行回数がベースライン実測値と比較される。ツールは比較結果から目標達成の合否を判定し、結果表と終了コードを出力する。

### 4.2 機能詳細

#### REQ-001: ワークスペース憲法（`.agents/AGENTS.md`）の12 KB以下圧縮と単一情報源化
- **概要**: 常時プロンプトへ注入される `.agents/AGENTS.md` から重複説明と詳細手順を分離し、システム側の自動切り詰めが発生しない 12,288 bytes 以下へ圧縮する。
- **レイヤー**: 両方
- **入力 / 処理 / 出力**: 入力は現行 `.agents/AGENTS.md`（37,876 bytes）および関連スキル群とする。処理では不変条件のみを憲法へ残し、詳細手順と参照表をオンデマンド文書へ移設して単一情報源化する。出力は 12,288 bytes 以下の `.agents/AGENTS.md`（自然言語）およびサイズ検証結果（プログラム）とする。
- **異常系**: 圧縮により不変条件（承認ゲート必須、コード先行禁止、機械チェック省略禁止、二重出力禁止）が欠落した場合、検証スクリプトは終了コード1を返す。単一情報源化した参照先ファイルが存在しない場合も、検証スクリプトが終了コード1を返し、エラー箇所を特定して修正する。
- **検証条件 (Acceptance Criteria)**:
  - プログラム判定: `.agents/AGENTS.md` のファイルサイズが UTF-8 で 12,288 bytes 以下であること。
  - プログラム判定: 圧縮後の `.agents/AGENTS.md` が参照するすべてのパスが実在し、`agent_def_check.py` が終了コード0を返すこと。
  - 自然言語判定: 圧縮後の憲法を読み込んだエージェントが、4原則・ID形式・承認定義・思考過程出力・末尾進行表示を欠落なく実行し、必須要素5項目を満たすこと。
  - 自然言語判定: 禁止事項（コード先行・チャット全文再掲・無断自律遷移）の違反が出力に含まれないこと。
  - REQ-001の自然言語判定にある必須要素と禁止要素の条件を、10回の試行のうち9回以上（合格率90%以上）で満たすこと。
- **優先度**: Must

#### REQ-002: ペルソナスキル群の軽量化とエージェント定義用手順のオンデマンド分離
- **概要**: オーケストレーターおよび各フェーズのペルソナスキルを重複排除により軽量化し、エージェント定義用の追加手順を別ファイルへ分離することで、各フェーズの指示書読込量をベースライン比50%以上削減する。
- **レイヤー**: 自然言語
- **入力 / 処理 / 出力**: 入力は Phase 0 判定結果（従来型プログラムまたはエージェント定義）および対象フェーズの承認済み文書とする。処理では重複記述を整理し、従来型プログラム開発においてエージェント定義用手順の読込なしで作業を進める。出力は対象フェーズの成果文書および思考過程3項目・進行表示1行を含む完了報告とする。
- **異常系**: Phase 0 で開発対象が判定不能な場合、安全側の「従来型プログラム」を仮置きし、推測で次工程へ進まず Product Owner に確認する。参照先ファイルが欠損している場合は即座に作業を停止し、欠損パスを報告する。
- **検証条件 (Acceptance Criteria)**:
  - 必須要素: 応答冒頭または開始報告に「現在地」「判断の根拠」「次の一手」の思考過程3項目が出力されること。また、応答末尾にDADA進行表示1行が出力されること。
  - 必須要素: 従来型プログラム指定の入力に対し、エージェント定義専用ファイルをロードせず Phase 1 から 4 の所定フォーマット（REQ-ID/TC-ID/UNIT-ID）で成果物を生成できること。
  - 必須要素: エージェント定義指定の入力に対し、分離されたエージェント定義用差分手順を確実にロードし、三原則と5パターン吟味を欠落なく出力できること。
  - 禁止要素: 指示書に記載のない項目や存在しないIDを創作して記載しないこと。
  - REQ-002の必須要素と禁止要素の条件を、10回の試行のうち9回以上（合格率90%以上）で満たすこと。
- **優先度**: Must

#### REQ-003: 執筆ワンパス化と機械検出箇所のみの局所推敲

## 5. 外部インタフェース要求

### 5.1 ユーザインタフェース (UI)
利用者はチャットプロンプトにより DADAプロセスまたは単体スキルを起動する。AIエージェントはすべての作業開始・完了のたびに思考過程3項目（現在地・判断の根拠・次の一手）を出力する。DADAプロセス実行中は応答末尾に進行表示1行（`[DADA | Phase N: ...]`）を出力する。成果物全文およびレビュー指摘全文は `docs/artifacts/` 配下のファイルへ書き込む。チャットへの出力はファイルパスと要約行のみに限定し、二重出力を防ぐ。承認ゲート型では定型フォーマットにより Product Owner へ明示的承認を求める。

### 5.2 ハードウェアインタフェース
本システムはソフトウェア定義とローカルスクリプトのみで構成される。実機デバイス操作や専用ハードウェア機器への直接接続は行わない。

### 5.3 ソフトウェアインタフェース
1. **統合機械検証CLI**: コマンド実行により対象ファイル・プロファイル・モードを受け取り、構造化レポートと終了コード（0=Highなし、1=Highあり、2=実行エラー）を返す。
2. **既存個別CLI後方互換**: 既存6スクリプト（`tools/dada_check.py`・`tools/asdoq_lint.py`・`tools/style_check.py`・`tools/agent_def_check.py`・`tools/office_io.py`・`tools/export_skillset.py`）の既存インタフェースを維持する。
3. **比較ベンチマークCLI**: ベースライン（v6.1.0）基準値と現在構成を比較し、要約・詳細表・終了コード（0/1/2）を返す。
4. **サブエージェント引き継ぎファイル**: フェーズ移行の引き継ぎでは `docs/process/last_phase_summary.md` を唯一の引き継ぎインタフェースとし、会話履歴の要約は渡さない。
5. **外部API連携（任意）**: `--decision1 on` が明示指定された場合のみ、`.env.local`、`.env`、または環境変数の `GEMINI_API_KEY` を用いて Google `gemini-decision-1` エンドポイント（`v1beta/decisions`）へリクエストを送信する。
