# docs/examples/ ディレクトリについて

本ディレクトリは、**利用者（Product Owner）向け**の使用例を格納します。AIエージェントが作業中に参照するファイルではありません。

## 格納ファイル

| ファイル | 中身 |
| :--- | :--- |
| `prompts_usage.md` | DADAプロセスを始めるための指示文（プロンプト）の見本集。4つの使い方（**P開発承認ゲート型 / P開発自律型 / A開発承認ゲート型 / A開発自律型**。PはProgram、AはAgentの略）について、そのままコピーできる指示文、それをやさしい言葉で書いた版、指示文の各行の意味、できあがるファイル、あなたがやること、選び方の目安、用語のやさしい言い換え表 |

## 使い方

1. `prompts_usage.md` を開きます。冒頭の「まず、2つの質問に答えてください」で、**何を作るか**と**どう進めるか**を決めます。
2. 決まったパターンの「コピー用の指示文」をチャットに貼り付けます。むずかしい言葉が気になる場合は、その下の「やさしい言葉で書いた版」を使ってもかまいません（意味は同じです）。
3. `[システムの要求]` のような角括弧の部分を、自分の言葉に置き換えます。ふつうの日本語で、箇条書き数行でかまいません。
4. AIが最初の返答で「何を作るか・どう進めるか・作業量の見積もり」を宣言します。**宣言が意図と違っていたら、その場で訂正を指示してください。**

> [!TIP]
> 何も指定しなくても動きます。「DADAプロセスで開発を開始してください。〜」と書くだけなら、**プログラム × 承認ゲート型**（区切りごとに確認する進め方）として、今までどおりに動きます。

> [!NOTE]
> 読んでいて意味の分からない言葉が出てきたら、`prompts_usage.md` の末尾にある**用語のやさしい言い換え表**を見てください。指示文やAIの返答に出てくる言葉を、進め方・作るもの・確かめ方・書類の名前の4つに分けて一覧にしています。

> [!NOTE]
> 完成した要求仕様書・設計書・総合テスト仕様のサンプルは、ここに置いていません。中身が古くなると、テンプレート本体のスキル・ひな形とずれます。文書の書き方は、作成スキルのスケルトン（`requirements-engineer` / `test-engineer` / `architect` の `references/`）と `docs/templates/agent/` を正とします。
