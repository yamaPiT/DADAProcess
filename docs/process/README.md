# docs/process/ ディレクトリについて

本ディレクトリは、DADAプロセスの**状態管理と文脈復元**を担うファイルを格納します。

## 格納ファイル

| ファイル | 役割 | 更新タイミング |
| :--- | :--- | :--- |
| `last_phase_summary.md` | **フェーズ間**の引き継ぎサマリー | `context-reset` スキル実行時にAIが自動更新 |
| `impl_progress.md` | **フェーズ内**（Phase 4）のユニット単位の実装進捗台帳 | Phase 4で1ユニット実装完了ごとにAIが更新 |
| `check_report.md` | 機械チェック（`tools/dada_check.py`）の結果 | チェック実行時に自動生成（Git管理対象外） |
| `agent_def_check_report.md` | エージェント定義チェック（`tools/agent_def_check.py`）の結果 | チェック実行時に自動生成（Git管理対象外） |
| `autoloop_log.md` | **自律型**の工程遷移ログ（遷移条件の判定根拠・PROCEED/HALTの判断） | 自律型で各Phase末にAIが1行追記 |
| `eval_report.md` | **エージェント定義開発**の評価セット（Eval Dataset）実行記録。試行ごとの結果と合格率 | Phase 4で評価セットを実行するたびにAIが更新 |
| `phase5_evaluation_guide.md` | Phase 5 評価ガイド（推奨。検収専用） | テンプレート。必要に応じてProduct Ownerが参照。SWP6への結果追記手順は含まない |

> [!NOTE]
> `autoloop_log.md` と `eval_report.md` は、実行モードが**自律型**の場合、または開発対象が**エージェント定義**の場合にのみ使用されます。既定値（従来型プログラム × 承認ゲート型）では更新されません。

## 運用ルール

1. **AIエージェント**は、フェーズの承認ゲート（承認ゲート型）または自律ゲート（自律型）を通過した後に `context-reset` スキルを実行し、`last_phase_summary.md` に現在の状態を書き出します。
2. **新しいコンテキスト**で作業するAIエージェントは、まず本ディレクトリの `last_phase_summary.md` を読み込み、前回の文脈を復元してから作業を開始します。コンテキストの作り方は動作モードと実行モードで異なります。
   - **モードX**（Antigravity 2.0 / CLI。推奨）: AIが自律起動するサブエージェント
   - **モードY × 承認ゲート型**: 人間が開始する新しいチャット
   - **モードY × 自律型**: 同一会話内の論理リセット（方式C）
3. **Phase 4の途中で会話が中断した場合**は、`impl_progress.md` の「未着手」のUNIT-IDと「次にやること」から再開します。実装をやり直す必要はありません。
4. 本ディレクトリのファイルは**人間が直接編集する必要はありません**。ただし、内容を確認して状態を把握することは推奨されます（特に `check_report.md` は、文書の健全性を一目で確認できます）。
5. **自律型で完走した後**は、`autoloop_log.md` を確認してください。どのPhaseがどの根拠で自動遷移したか、途中で停止した場合はその理由が記録されています。人間の承認ゲートを省略した分の透明性を、このログが担保します。
6. **エージェント定義開発では** `eval_report.md` を確認してください。自然言語レイヤーの振る舞いは確率的なため、試行回数と合格率で判定します。試行1回だけの記録は不合格として扱われます。

## なぜ状態をファイルに書き出すのか

AIの一時記憶（コンテキストウィンドウ）は有限で、長い作業では過去の内容が押し出されて消えます。状態をファイルへ外部化しておくことで、**記憶が消えても作業を続行できる**状態を保ちます。これはDADAプロセスの「アテンション・リセット」を成立させるための土台です。
